# Add social cards (Open Graph + X) so shared links render a preview
status: done
agent: claude sonnet

## What the user asked
A link to any page of https://jev-atlas.vercel.app posted on X should render a
large summary card, with `og:image`/`twitter:image` returning a real
1200×630 PNG, using the site's own visual language.

## What changed
- Root layout now sets `metadataBase` (from `NEXT_PUBLIC_SITE_URL`, same
  localhost fallback as `sitemap.ts`), `openGraph` (siteName/type/locale, no
  hardcoded title/description so every route's own `title`/`description`
  flows through automatically), and `twitter.card = "summary_large_image"`.
- `src/app/opengraph-image.tsx` and `src/app/twitter-image.tsx` render the
  default card: masthead "J · JEV ATLAS", label "JEV ATLAS · INDEPENDENT
  FIELD GUIDE", headline "What can you actually build with Jev?", footer
  built from `loadAnalysis()` counts ("31 build blueprints · 9 tracked
  claims · MCP for your coding agent") — no hardcoded counts.
- One `opengraph-image.tsx` added inside each of `ideas/[slug]`,
  `projects/[slug]`, `patterns/[slug]`, `claims/[slug]`: label is the
  record kind + evidence status ("BUILD BLUEPRINT · AUTHORED HYPOTHESIS",
  "EVIDENCE LEDGER · PLAUSIBLE", etc.), headline is the record title
  (truncated at 170 chars with an ellipsis, font size scales down for long
  titles so nothing overflows the fixed 630px height).
- Shared renderer in `src/lib/social-card.tsx`: paper/ink/accent tokens
  copied from `globals.css`, Source Serif 4 (headline) and IBM Plex Mono
  (labels) fetched from Google Fonts at module scope and reused across every
  card (no new npm dependency — `next/og` ships with Next; fonts come over
  `fetch`, cached once per build/runtime, not per request).
- `test/social.test.ts`: unit tests for `truncateHeadline`, the
  default-card copy (asserts it reads `31`/`9` from a fake analysis object
  and from the real `data/processed/analysis.json` via the `null` fallback
  path), and per-kind record card labels including the longest real claim
  title, to lock in "never overflow."

**Bug caught and fixed during verification:** the first font-loading
attempt picked the *first* `@font-face` block Google returns for a family
(a narrow Cyrillic-range subset), so most Latin glyphs silently fell back to
satori's default font and only a few letters rendered in the real
serif/mono — visually broken (patchy bold/regular mix mid-word). Fixed by
selecting the block whose `unicode-range` covers `U+0000-00FF` instead of
the first match; re-verified visually after the fix.
