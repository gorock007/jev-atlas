## What the user asked
Complete the pre-launch hardening pass: add security headers and a working CSP, make unknown record slugs return real 404 responses, constrain research Markdown links, prevent model-authored fit-check text from carrying HTML into copied Markdown, test those boundaries, and verify the production server.

## What changed
- Added one header rule for every route with the requested response headers and a production CSP. Production allows scripts from `'self'` plus `'unsafe-inline'`: Next 16's statically generated HTML contains inline React flight/bootstrap scripts, and nonce CSP would force the whole static atlas into dynamic rendering. Styles, fonts, and connections remain `'self'`; images additionally allow `data:`. Development alone adds `'unsafe-eval'` and inline styles for React debugging and hot reload.
- Closed the generated slug sets for claims, projects, patterns, ideas, and research with `dynamicParams = false`. Missing slugs now return HTTP 404 before page streaming; existing in-page `notFound()` checks remain as defense in depth.
- Added a research-Markdown href allowlist for http(s), `mailto:`, single-slash site-relative paths, and fragments. Protocol-relative, backslash-prefixed, non-http schemes, and ordinary relative URLs render as plain text instead of anchors.
- Confirmed every fit-check model field is rendered as a React text child in `src/components/fit-checker.tsx`. Added angle-bracket stripping at the shared `postValidate` clamp so the same model text cannot become HTML in the copy-as-Markdown representation.
- Extended security tests across the header contract, Markdown href allowlist, static slug closure and traversal-shaped slug, and hostile model output.
