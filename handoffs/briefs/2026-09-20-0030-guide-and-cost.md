1. **`/guide` — "Ask Jev well".** Seven practical techniques, each = a short
   heading, 2–3 plain sentences, a tiny before/after or diagram where it helps,
   and a source link. Written in our own words, simple language, no hype:
   1. Rebuild the option list from the current state at every step (source: Browser Use jev-ultrafast repo).
   2. Send independent questions together; questions cannot read each other's answers, so fetch first, then ask (docs.typesafe.ai/cookbooks/parallel_questions).
   3. Put the real requirement in the question text and describe every option — the model never sees the question id (docs.typesafe.ai/primitives/choice).
   4. Give evidence, not summaries: pass the sources/findings/gaps as separate state fields.
   5. Confidence is not accuracy; set your review threshold from your own labelled examples (docs.typesafe.ai/confidence).
   6. Big candidate lists: filter in code → Score the rest → Choice among a shortlist (Choice allows up to 255 options).
   7. A confident answer never proves an action happened: verify outcomes separately, and keep action limits, spend limits and saved progress in code.
   End with "What stays in code / what stays with an LLM / what goes to Jev" as a three-column picture and links to `/fit` and `/map`.
2. **`/cost` — decision-cost calculator.** Client component: inputs = decisions
   per day, input tokens per decision, price per million input tokens

   month / per 10,000 decisions, a bar comparing it with an editable
   "your current cost per decision", and one fixed caveat line: track cost per
   completed task — a cheap wrong decision can cost more than the call. Pure
   arithmetic in `src/lib/decision-cost.ts` with a node:test file. No network.
